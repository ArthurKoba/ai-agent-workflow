# Тестирование бизнес-логики

Проверяй предметное правило через вход того модуля, которому оно принадлежит. Это может быть библиотека, клиент, сервис или локальное приложение.

## Выбери различающие случаи

- Для группы входов с одинаковой обработкой возьми представителя. Для упорядоченного порога добавь саму границу и ближайшие представимые значения с обеих сторон. При пороге ≥ 100,00 вход 100,01 выявит ошибочное условие «ровно 100,00», хотя при правильном расчёте 100,00 и 100,01 дают один исход.
- Для решения из нескольких условий задай таблицу сочетаний и действий. Проверь совпадение нескольких правил, отсутствие совпадений и приоритет. Сочетание, невозможное внутри модели, проверяй отдельно на входной границе, если оно может прийти извне. Для разных примеров одного правила достаточно таблицы входов и ожидаемых результатов.
- Для последовательности действий задай исходное состояние, событие, следующий статус и значимый эффект. Проверь допустимый и запрещённый переход, повтор и промежуточный отказ, если они предусмотрены. Например, после отказа изменить заказ сверь неизменный статус и отсутствие нового списания. Проверь ранее созданные данные, если их обработка входит в контракт.

## Проверь расчёт и время

- Сверяй точный результат с независимо рассчитанным значением. Для денег задай валюту, точность, режим и момент округления. Подбери пример, где округление строк и итога различается. В Python `Decimal` из строки сохраняет исходное десятичное значение. Преобразование через `float` может его исказить. Для общей целочисленной формулы добавь отрицательный пример. Деление целых Python оператором `//` округляет вниз, деление TypeScript `bigint` и целых C++ усекает к нулю. Для приближённых расчётов бери допуск из контракта.
- Для календарного срока задай зону и включённость границы. Если смена смещения может повлиять на правило, проверь повторяющееся или пропущенное местное время. Длительность внутри процесса проверяй по управляемым монотонным часам.
- Для инварианта на широком диапазоне используй генерируемые случаи. Убедись, что генератор достигает существенных классов и предусловий. Например, сохранение общей суммы может выполняться, даже если вся сумма ошибочно досталась одному получателю. Добавь различающий пример или проверку отдельных долей. Сохраняй минимальный воспроизводимый контрпример.

## Проверь исход операции

Вызывай публичную операцию и сверяй результат, новое состояние и обещанные эффекты. Управляй значениями часов, идентификаторов и внешних ответов, если они определяют исход. Проверяй порядок вызовов, когда он входит в контракт. Если гарантия зависит от закрепления записи или отката, используй [проверку хранилища](client-server.md#хранилище-и-асинхронная-доставка). Пользовательское представление итога и следующее действие проверяй в [интерфейсе](user-interface.md#пользовательский-переход).
