# Тестирование клиент-серверных границ

Используй главу для обмена между процессами, записи и доставки, включая адаптеры внешних систем.

## Установи контракт обмена

- Определи обещания клиента и поставщика. Проверь значимые поля, единицы, значения по умолчанию и ошибки. Если контракт включает порядок или пагинацию, подбери данные, на которых видны пропуск и повтор. Проверь совместимость поддерживаемых версий. Для HTTP сверяй статус, заголовки и тело. При несовместимом вводе проверь отказ и отсутствие нежелательных эффектов.
- Проверяй кодирование и декодирование на независимо заданных сообщениях. Точное совпадение байтов нужно для канонического формата. Например, большой идентификатор из Python может потерять точность при чтении JSON-числа клиентом на TypeScript. Самопроверка производителя с его же декодером может этого не обнаружить.
- Для защищённой операции подготовь допустимого субъекта, запрос без действительных учётных данных и субъекта без нужного права. Сверь ответ, видимость данных и отсутствие запрещённых изменений.

## Выбери границу исполнения

Управляемый ответ проверяет реакцию клиента на заданное сообщение. Проверка поставщика воспроизводит согласованные взаимодействия на нужной версии сервера. Для правил маршрутизации и обработки ответа может хватить запуска приложения в процессе. Если гарантия зависит от серверного запуска, передачи потока или закрытия соединения, используй реальный транспорт. Когда решает доступ из целевой среды, выбери [проверку развёрнутой интеграции](operations.md#развёртывание-и-внешние-системы).

## Проверь отказ и повтор

Различай недоступность до обработки, отклонение команды и потерю ответа после закрепления эффекта. Для последнего случая воспроизведи отказ в этой фазе, повтори команду по предусмотренным правилам и сверь результат и число эффектов. При отмене уточни, какая сторона её подтверждает и что уже могло сохраниться.

## Хранилище и асинхронная доставка

- Для транзакций, ограничений и конкурентных запросов используй поддерживаемый движок с нужными свойствами конфигурации. Проверь видимость записи из независимого соединения и состояние всех затронутых данных после частичного отказа. Для гарантии при конфликте задай порядок двух транзакций и сверь конечный инвариант после предусмотренного повтора. Миграцию запускай с поддерживаемой старой схемы и представительными данными. Сверь преобразования и новые ограничения.
- Для очереди или задания разделяй приём, завершение операции и подтверждение доставки. Если сообщение может прийти повторно, воспроизведи сбой после записи эффекта и до подтверждения и проверь фактический результат повторной обработки. Для гарантий, которые относятся к брокеру, используй его реальную конфигурацию. Если порядок гарантирован внутри группы, проверь значимый сценарий с несколькими группами. Для сохранности после перезапуска проверь состояние из нового процесса.
- Для потока воспроизводи существенные сочетания частичного ввода, задержки и переподключения. Сверяй данные по идентификатору операции или версии. Для внешнего провайдера используй управляемые ответы на отказ и тестовую среду провайдера, когда гарантия зависит от его реализации протокола.
