# Scientific Literature Search and Source Verification

Use for state-of-the-art review, prior-work comparison, finding
scientific sources, fact-checking citations and bibliographies.
The objective is **relevant evidence and critical synthesis**, not
an arbitrary quota of references.

## Scope the search

1. Translate the research question into concepts, synonyms, technical
   terms, alternative approaches, years and language/domain coverage.
   Search more than one suitable scholarly source when available:
   publisher and conference archives, journals, institutional records,
   trusted academic indices, and applicable national databases.
2. Use successive search passes to close concrete coverage gaps
   (closest competing methods, recent work, local-language research,
   older foundational methods, relevant software/hardware evidence).
   Avoid repeating broad searches without a new lead.
3. Keep search terms, dates, accessible original records, inclusion/
   exclusion criteria and unresolved access gaps. Do not bypass a
   paywall or assume that a search-result snippet is a full text.
   The paper's first page, metadata and abstract establish
   different levels of visibility.

## Verify a source before citing it

Check the **actual work's** title, authors, date, venue, type,
volume/issue/pages and DOI or permanent URL where available.
Verify the bibliographic data against a primary publisher,
conference or institution record; never fabricate missing fields.

For each specific scientific claim record the evidence level:
**full text**, **abstract only**, **metadata only** or
**source-code/documentation check**. An abstract does not support
unmentioned numerical results, equations, hidden parameter choices
or full algorithm behavior. A DOI, library repository, index entry,
journal card or university page alone does not certify peer review,
publication status or indexing in a particular database.

Keep methodological scientific evidence separate from engineering
implementation evidence: peer-reviewed research for research claims;
versioned source code for actual implementation behavior;
vendor documentation for a particular API. A code repository or
web tutorial does not become a peer-reviewed scientific publication.

## Synthesize, don't list abstracts

Group literature by the **research problem and comparable difference**:
inputs, assumptions, procedure, validation, result and acknowledged
limitations. Explicitly flag non-comparable baselines and unavailable
information. A weakness shown in one paper is not proof that all
methods in its family share that weakness. Review comments are
not author findings; check subsequent replies or corrected versions.

Use traceable stable citation IDs when supported; leave numbering and
rendering to the actual document toolchain. Bibliographic formatting
follows the verified venue or applicable standard, **not** a presumed
universal GOST, APA or IEEE style. A page locator is required for a
direct quotation when the applicable convention calls for one.
Attributing a version from a secondary source is not an acceptable
substitute for checking the original.

Preserve a short verification ledger per newly added reference:
claim, stable source ID, primary locator, accessed material,
checked metadata, evidence level, peer-review/indexing status
when provable, and unresolved questions. Avoid multiple conflicting
source registers. Do not add references only to satisfy a count.

**Completion:** every substantive literature-derived claim is tied
to a properly identified source and explicit evidence scope;
missing access or disputed facts remain visible.
