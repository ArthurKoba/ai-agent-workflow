# Проектирование и аудит тестов

Применяй навык, когда нужно спроектировать тесты, выбрать прогоны или оценить существующий набор. Начни с [общих правил](fundamentals.md), затем прочитай разделы по затронутым гарантиям.

| Что может сломаться | Что читать |
| --- | --- |
| Расчёт, предметное правило, переход состояния | [Бизнес-логика](business-logic.md) |
| Взаимодействие в браузере, форма, навигация или доступность | [Веб-интерфейс](user-interface.md#веб-интерфейс) |
| Нативное окно, диалог, ввод или отрисовка | [Desktop](user-interface.md#desktop-и-нативное-поведение) |
| Жизненный цикл приложения Android или iOS, разрешения, работа без сети | [Мобильные приложения](user-interface.md#нативные-мобильные-приложения) |
| Формат обмена, контракт клиента и поставщика, запись или доставка | [Клиент-серверные границы](client-server.md) |
| Запуск команды, вывод, эффекты скрипта или повтор | [CLI и автоматизация](operations.md#cli-и-автоматизация) |
| Установка, конфигурация, выкладка или доступ к провайдеру из целевой среды | [Развёртывание и внешние системы](operations.md#развёртывание-и-внешние-системы) |
| Измерение пользовательского результата, цель или обязательство за период | [SLI, SLO и SLA](operations.md#уровень-сервиса) |

Для интерфейсов также прочитай [общий блок о пользовательском переходе](user-interface.md#пользовательский-переход).

Если изменение затрагивает несколько границ, выбери раздел для каждой отдельной гарантии. Например, правило скидки проверяется в логике, возможность исправить ввод после отказа — в интерфейсе, формат отказа — на границе обмена.
